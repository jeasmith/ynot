# Bound hashtags by whitespace rather than by character set

A tag lives inside a YNAB memo, sharing one 500-character free-text field with the user's own prose. The grammar therefore has two jobs at once: recognize what the user meant as a tag, and never damage what they meant as writing.

Defining a character set — ASCII letters, digits, hyphens — and ending a tag wherever that set ends was the first instinct, and it truncates. `#Home_Repair` becomes `#Home`, `#Café` becomes `#Caf`, and a later rename of `#Home` then reaches into a string the user never thought of as a tag. Deciding where a word ends is not Ynot's call to make.

A tag instead runs from its `#` to the next whitespace. The user drew that boundary themselves when they pressed space, no token is ever cut in half, and Unicode stops being a special case. What the rule costs is prose punctuation — "Weekly shop #Household." would otherwise carry a tag distinct from `#Household` — so trailing punctuation is trimmed back off and the full stop stays in the sentence where it was typed.

## Consequences

- A tag is recognized in this order: find a `#` at the start of the memo or preceded by a character that is neither a letter nor a digit, and not preceded by `\`; skip any further `#` immediately after it; take the run of non-whitespace characters; trim trailing punctuation; reject the result if it is empty or made only of decimal digits. Order matters — trimming precedes the digit test, so `#3.` is prose rather than a tag.
- Those three tests are defined by Unicode property rather than by an ASCII list, because the tag text itself is unrestricted and an ASCII list would silently give non-Latin writers a different grammar. A *letter or digit* before the `#` means general category `L*` or `N*`, so `é#tag` and `中#tag` are rejected exactly as `catalogue#kitchen` is. *Trailing punctuation* means general category `Po`, `Pe` or `Pf`, which covers the ASCII `. , ; : ! ? ) ] } " '` and equally `#家計。`, `#Household”` and `#買い物」`, while deliberately excluding dashes (`Pd`) and connectors (`Pc`) so `#Home-` and `#Home_` keep the characters the user typed. *Digits* for the rejection test means decimal digits only (`Nd`), so `#٣` is a number just as `#3` is, while `#Ⅻ` stays a tag.
- The start rule exists to keep prose out of the vocabulary. `catalogue#kitchen` and `C#` are not tags, because a letter precedes the `#`. `Paint,#Home-Repair` and `(#Tax` are, because punctuation is forgiving where a letter is not.
- There is no character-set restriction. `#Café`, `#Grüße`, `#Home_Repair` and `#Cornwall-2026` are all ordinary tags, and a hyphen carries no special meaning.
- Tag identity is the tag normalized and then case-folded. Normalization matters as soon as Unicode is allowed: a precomposed `é` and a decomposed `e` plus combining accent are visually identical, so without it they would form a duplicate pair no human could tell apart.
- A token of digits alone is not a tag. `Flat #3`, `Invoice #1234` and `Table #7` are common in real memos, and every boundary rule above would otherwise read them as tags. The cost is that a bare year such as `#2026` must be written `#Y2026` or, better, `#Cornwall-2026`.
- `\#` marks a literal hash that is never a tag. It is the only escape sequence; every other backslash is left untouched, so `C:\#temp` needs no thought. The user types it — Ynot never inserts one, because writing a backslash into prose that YNAB will display everywhere is exactly the unrequested edit [ADR 0003](0003-tag-reader-vocabulary-warnings.md) forbids.
- The canonical display spelling is the spelling carried by the most transactions — distinct transactions rather than raw occurrences, so a memo that repeats a tag still counts once and the rule agrees with how membership and totals count it. Ties break toward the spelling on the earliest transaction by date, and if that is still tied, toward the lower spelling by code point, so the answer never depends on the order YNAB happened to return the rows in. It cannot be a stored user preference, because Ynot persists nothing outside YNAB, so it is derived from the transactions every session. It is therefore free to change as the data changes — which is honest, and the permanent cure is the rename that the case-collision warning already offers. Canonical spelling governs display only; membership and totals run on the folded identity.
- Applying a tag appends it with a single space and re-orders nothing. An empty memo becomes the tag alone. Applying a tag the transaction already carries by identity is a no-op: rewriting `#household` to `#Household` would be an unrequested edit, and the collision warning is the proper place to offer it.
- A memo that cannot fit the tag within YNAB's 500-character limit is skipped and reported in the impact preview, never truncated. Truncation destroys the user's own words to make room for Ynot's metadata, cannot be undone from YNAB, and outlives session-only undo. Failing loudly on four transactions is recoverable; silently eating the tail of a memo is not. Refusing the whole batch instead would let one long memo block forty valid ones.
- The 500-character limit is treated as a floor rather than a target. "500 characters" is ambiguous once non-ASCII is allowed — a character may count as one, two or four units depending on how YNAB measures — so the fit check leaves a margin instead of discovering the boundary through failed writes on a real budget.
- The same tag repeated in one memo is one membership and one contribution to the total. Counting it twice would silently double a Tag Total.
- A doubled marker such as `##Household` reads as `#Household`, and a repeated tag is accepted as written. Both raise a vocabulary warning ranked below duplicate spellings: nothing is broken, membership and totals are already correct, but a repeated tag burns characters the user's prose may later need. These are the only warnings whose cure is guaranteed safe — collapsing a marker or dropping a repeat changes no total — and, unlike the single-use signal, fixing one removes it permanently, which matters when no dismissal can be persisted. Tidying many memos is one operation under one preview, the same shape as a global rename, so it does not reopen ADR 0003's rejection of staged batches.
- Removing a tag closes the gap it leaves and changes nothing else, per ADR 0003. Every rewrite operates on the raw memo text rather than the displayed text, or a rename would write back the escape-stripped form and turn a literal `\#` into a real tag on the next read.
- This grammar governs parent memos. Whether a hashtag inside a split line's memo is parsed at all is a membership question, deferred to issue #8.
